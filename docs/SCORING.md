# Как взять максимум по рубрике Demo Day (100 баллов)

Источник: Положение п. 5.7.2. Важно из п. 5.7.3: итог решается коллективным обсуждением жюри, арифметика вторична.
Значит, побеждает проект, который жюри может пересказать друг другу одной фразой: «команда X решает боль Y, показали вживую, это масштабируется».

## Сводка: где лежат баллы

| Критерий | Баллы | Что реально проверяется | Чем доказываем |
|---|---|---|---|
| Ценность решения | 25 | Конкретный человек, конкретная боль, польза видна в демо | Персона + цифра боли + метрика «до/после» на экране |
| Результат и качество | 20 | Заявленный сценарий проходит от входа до результата, результат полезен сам по себе | Живое демо без обрывов, структурированный результат (экспорт, оценка, план), не «сырой текст» |
| Потенциал масштабирования | 20 | Путь после хакатона: кто ещё, как внедряется, сколько стоит | Юнит-экономика, лестница внедрения, точки интеграции |
| Презентация, демо, ответы | 20 | Ясность, убедительность демо, ответы без пауз | Репетиция, тайминг, бэкап-видео, заготовленные ответы |
| Инновационность | 15 | Отличие от очевидных альтернатив, собственное преимущество | Явный ответ «чем не ChatGPT», один нестандартный механизм |

45 баллов (ценность + результат) даёт узкий, работающий, показанный вживую сценарий. Это главный вывод: одна цепочка, доведённая до конца, бьёт три недоделанные.

## 1. Ценность решения (25)

**Максимум даёт:**
- Одна персона с именем и контекстом: «Айгерим, учитель биологии, 7 классов, 180 учеников». Не «сфера образования».
- Боль в цифрах: «тратит 3–4 часа в неделю на дифференцированные задания» / «половина класса не понимает тему, учитель узнаёт об этом на контрольной через 2 недели».
- Польза очевидна из демо, а не из слов: показать «было» (ручной процесс, 40 минут) и «стало» (2 минуты, результат на экране).
- Совпадение с приоритетами партнёра ASU: персонализация, поддержка преподавателя, измеримый учебный результат.

**Теряют баллы:** «для всех школ Казахстана», проблема без цифр, польза, которую надо додумывать, решение боли, которой нет у конкретного человека.

**Проверка в 16:30:** может ли член жюри за 10 секунд ответить «кому и чем это помогает»?

## 2. Результат и качество (20)

**Максимум даёт:**
- Сценарий проходит целиком: вход → работа агента → результат, который можно взять и использовать (DOCX, таблица оценок, план с датами, тест с ключами).
- Качество результата видно: цитаты из источника, уровни сложности, обоснования оценок, а не абзац общих слов.
- Ноль обрывов: DEMO_MODE и заранее загруженные данные, если сеть или API подведут.
- Шаги агента видны на экране: жюри понимает, что работает система, а не один промпт.

**Теряют баллы:** демо ломается, результат выглядит как ответ ChatGPT, сценарий показан наполовину, «а вот это мы не успели» посреди демо.

**Проверка в 16:30:** прогнать демо 3 раза подряд без единого клика мимо. Замерить: не дольше 90 секунд.

## 3. Инновационность (15)

**Максимум даёт один явный механизм**, которого нет у «очевидной альтернативы» (ChatGPT, готовые EdTech-платформы):
- grounding: ответы только из материалов школы с цитатами, «не знаю» при отсутствии;
- mastery-подход: карта пробелов ученика, обучение только по пробелам, повторная проверка;
- сократовский режим: агент не даёт ответ, ведёт наводящими вопросами;
- агент-проверяющий: второй агент валидирует результат первого по рубрике перед показом;
- human-in-the-loop: учитель утверждает, система обосновывает;
- KZ/RU/EN с согласованным глоссарием терминов.

Назвать механизм словами на слайде «Чем отличаемся» и показать его в демо.

**Теряют баллы:** «мы используем GPT-4», «чат-бот для учеников», сравнение только с «ничего».

## 4. Потенциал развития и масштабирования (20)

**Максимум даёт конкретика, а не «добавим функции»:**
- Лестница: 1 учитель → школа → район/управление образования → 7 000+ школ РК → страны-партнёры ASU.
- Юнит-экономика: стоимость одного урока/проверки в тенге (взять из latency_ms и токенов ответа API), время учителя в часах.
- Точки интеграции: Kundelik, Bilimland, LMS вуза, госуслуги образования. Один слайд со схемой.
- Данные и приватность: локальное хранение, анонимизация, контроль учителя. Это снимает главный барьер внедрения.
- Расширение сценариев: тот же движок для другого предмета/уровня одним конфигом.

**Теряют баллы:** отсутствие цифр, «монетизацию придумаем», зависимость от одного датасета или ручной настройки.

## 5. Презентация, демо и ответы (20)

**Максимум даёт:**
- Структура 8 слайдов из PITCH.md, 3 минуты речи + 90 секунд демо. Репетиция минимум 3 раза с таймером.
- Первые 20 секунд: персона и боль. Никаких «мы команда Ads Tech, мы использовали FastAPI».
- Демо ведёт один человек, второй говорит. Бэкап: видео 60 секунд на телефоне и ноутбуке.
- Ответы на 6 вопросов заготовлены (см. ниже), каждый не длиннее 20 секунд.
- Честность: слайд «что не успели» повышает доверие, жюри всё равно спросит.

**Заготовленные ответы:**
1. Чем лучше ChatGPT? → материалы школы + структурированный результат + память прогресса + проверяемость цитатами.
2. Галлюцинации? → grounding, «не знаю», учитель утверждает.
3. Сколько стоит? → цифра за запрос, показать latency в UI.
4. Откуда данные и права? → свои материалы школы, открытые данные, синтетика для демо, всё в THIRD_PARTY.md.
5. Как внедрять? → лестница 1 учитель → школа, интеграции.
6. Что делали сами за 5 часов? → вся доменная логика, история коммитов, шаблон раскрыт.

| 14:00 | Сценарий end-to-end (результат 20). |
| 15:00 | Результат структурирован и экспортируем, шаги агента видны (результат 20, инновация 15). |

| 16:30 | Самоаудит по этому файлу: 5 вопросов, 5 честных ответов. Резать всё, что не даёт баллов. |
| 17:40–18:00 | Слайд «что не успели», README. |
| 24–28.09 | Слайды, репетиции, видео-бэкап, заготовленные ответы. |

## Не забыть про фильтр до Demo Day

До жюри доходят только финалисты техпроверки 24–28.09. Её критерии в ТЗ трека, появятся в 13:00, и там свои баллы. Плюс AI-судья читает репозиторий. Поэтому README, запуск одной командой и история коммитов не менее важны, чем питч: без них до 100 баллов Demo Day не добраться.
