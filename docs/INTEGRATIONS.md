# Интеграции: 1С через OData и Bitrix24

Статус: архитектура и контракт адаптеров готовы (`backend/app/integrations.py`), сегодня данные идут через выгрузки 1С в xlsx/CSV. Подключение к живой базе 1С и порталу Bitrix24 — следующий шаг внедрения, без изменения движка.

## 1С:Предприятие — стандартный интерфейс OData

Вход (чтение) вместо файлов:

| Наши данные | Объект 1С (OData `…/odata/standard.odata/`) | Примечание |
|---|---|---|
| products | `Catalog_Номенклатура` (Код, Наименование, Артикул, ЕдиницаИзмерения, кратность из реквизитов) | справочник |
| suppliers, сроки поставки | `Catalog_Контрагенты` + `Catalog_ДоговорыКонтрагентов`, срок поставки из реквизита/условий | справочник |
| sales | `Document_РеализацияТоваровУслуг` (шапка: Дата, Контрагент → обезличенный ID; табличная часть Товары: Номенклатура, Количество, Цена) | история продаж, клиент хешируется на нашей стороне |
| stock | `AccumulationRegister_ТоварыНаСкладах/Balance(Period=…)` | остатки по складам на дату |
| in_transit | `Document_ЗаказПоставщику` (не закрытые) + ожидаемая дата поступления | товар в пути |
| stockouts | выводятся из истории остатков (`…/Turnovers` по периодам) | дефицит |

Выход (запись): утверждённый заказ → `POST Document_ЗаказПоставщику` (Контрагент, Склад, Товары: Номенклатура, Количество, ДатаПоступления), проведение по решению менеджера. Обмен: расписание раз в сутки (утренний агент), инкрементально по `DataVersion`.

## Bitrix24 (REST)

| Сценарий | Метод | Что даёт |
|---|---|---|
| Согласование заказа | `tasks.task.add` на ответственного (ссылка на заказ, сумма, срочность) или `bizproc.workflow.start` | утверждение в привычном контуре компании |
| Уведомление о дефиците | `im.notify.system` / `im.message.add` в чат отдела закупа | утренняя сводка агента прямо в мессенджер |
| Карточка поставщика | `crm.company.get/update` | контакты и условия поставщика для писем и сроков |
| Отчёт руководителю | `disk.folder.uploadfile` (XLSX заказов, отчёт об избытках) | еженедельная выгрузка |

Правило ТЗ сохраняется: отправка заказа поставщику только после подтверждения ответственного, интеграции создают задачи и черновики, не отправляют сами.

## Наш ассистент внутри Bitrix24 (не ChatGPT, а наш агент)

Да, это возможно без изменений движка. Bitrix24 выступает только каналом: сотрудник пишет в привычный чат, а отвечает наш агент с инструментами движка (обоснование позиции, what-if, критичные позиции, черновик письма). Модель под агентом любая из раздела «LLM»: OpenAI, NVIDIA NIM или локальная; Bitrix24 к ней напрямую не обращается.

**Вариант 1. Чат-бот «Закупщик» в мессенджере Bitrix24 (рекомендуем).**
1. Локальное приложение Bitrix24 регистрирует бота: `imbot.register` (в новых версиях `imbot.v2.Bot.register`) с обработчиком события `ONIMBOTMESSAGEADD` на наш адрес, например `https://<наш-сервер>/api/integrations/bitrix24/bot`.
2. Сотрудник пишет боту: «почему по 010300016_ столько?». Bitrix24 присылает событие с текстом (`data[PARAMS][MESSAGE]`), диалогом (`DIALOG_ID`) и токеном портала.
3. Наш сервер передаёт текст в тот же цикл агента, что и `POST /api/chat`: модель вызывает `explain_sku`, `what_if`, `list_orders` и отвечает по числам движка.
4. Ответ уходит обратно методом `imbot.message.add` в тот же диалог. Утренняя сводка агента по расписанию отправляется так же в чат отдела закупа.
Требования: HTTPS-адрес нашего сервера, доступный порталу (облако) или внутренняя сеть (коробочная версия Bitrix24), права приложения `imbot`, `im`.

**Вариант 2. Наш сервис как AI-движок BitrixGPT (CoPilot).** Метод `ai.engine.register` (категория `text`, свой `completions_url`) делает наш сервис одним из AI-провайдеров внутри Bitrix24. Bitrix24 присылает `prompt` и контекст, мы отвечаем 202 за 5 секунд, а готовый текст отправляем на `callbackUrl`. Подходит, если нужен наш ассистент прямо в интерфейсе CoPilot; доступно в облачном Bitrix24, нужен скоуп `ai_admin`. Для закупщика вариант 1 естественнее: бот видит только вопросы про заказы.

**Вариант 3. Согласование заказов.** Утверждение из нашего интерфейса создаёт задачу `tasks.task.add` ответственному с суммой и списком позиций; статус задачи возвращается к нам событием. Это закрывает требование ТЗ «утверждение сотрудником» в привычном для компании контуре.

Что уже готово в коде: цикл агента и инструменты (`backend/app/llm.py`, `backend/app/tools.py`), тот же вход, что понадобится обработчику бота (`run_agent`). Не реализовано: HTTP-обработчик событий Bitrix24 и регистрация бота (оценка: 2–3 часа с тестовым порталом).

Документация Bitrix24: [imbot.register](https://apidocs.bitrix24.com/api-reference/chat-bots/outdated/bots/imbot-register.html), [ONIMBOTMESSAGEADD](https://apidocs.bitrix24.com/api-reference/chat-bots/messages/events/on-imbot-message-add.html), [imbot.message.add](https://apidocs.bitrix24.com/api-reference/chat-bots/messages/imbot-message-add.html), [ai.engine.register](https://apidocs.bitrix24.ru/api-reference/ai/ai-engine-register.html).

## Как это устроено в коде

`backend/app/integrations.py` описывает интерфейсы `DataSource` (получить products/suppliers/sales/stock/in_transit/stockouts как DataFrame) и `OrderSink` (передать утверждённый заказ / уведомление). Реализации: `CsvSource` (сегодня, работает), `OneCODataSource` и `Bitrix24Sink` (каркас с маппингом объектов выше, требуют URL и учётные данные, помечены `NotImplementedError`). Движок и API от источника не зависят: `Dataset` строится из любого `DataSource`.
