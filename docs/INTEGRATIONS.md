# Интеграции: 1С через OData и Bitrix24

Статус: архитектура и контракт адаптеров готовы (`backend/app/integrations.py`), сегодня данные идут через выгрузки 1С в xlsx/CSV. Подключение к живой базе 1С и порталу Bitrix24 — следующий шаг внедрения, без изменения движка.

## 1С:Предприятие — стандартный интерфейс OData

Вход (чтение) вместо файлов:

| Наши данные | Объект 1С (OData `…/odata/standard.odata/`) | Примечание |
|---|---|---|
| products | `Catalog_Номенклатура` (Код, Наименование, Артикул, ЕдиницаИзмерения, кратность из реквизитов) | справочник |
| suppliers, сроки поставки | `Catalog_Контрагенты` + `Catalog_ДоговорыКонтрагентов`, срок поставки из реквизита/условий | справочник |
| sales | `Document_РеализацияТоваровУслуг` (шапка: Дата, Контрагент → обезличенный ID; табличная часть Товары: Номенклатура, Количество, Цена) | история продаж, клиент хешируется на нашей стороне |
| stock | `AccumulationRegister_ТоварыНаСкладах/Balance(Period=…)` | остатки по складам на дату |
| in_transit | `Document_ЗаказПоставщику` (не закрытые) + ожидаемая дата поступления | товар в пути |
| stockouts | выводятся из истории остатков (`…/Turnovers` по периодам) | дефицит |

Выход (запись): утверждённый заказ → `POST Document_ЗаказПоставщику` (Контрагент, Склад, Товары: Номенклатура, Количество, ДатаПоступления), проведение по решению менеджера. Обмен: расписание раз в сутки (утренний агент), инкрементально по `DataVersion`.

## Bitrix24 (REST)

| Сценарий | Метод | Что даёт |
|---|---|---|
| Согласование заказа | `tasks.task.add` на ответственного (ссылка на заказ, сумма, срочность) или `bizproc.workflow.start` | утверждение в привычном контуре компании |
| Уведомление о дефиците | `im.notify.system` / `im.message.add` в чат отдела закупа | утренняя сводка агента прямо в мессенджер |
| Карточка поставщика | `crm.company.get/update` | контакты и условия поставщика для писем и сроков |
| Отчёт руководителю | `disk.folder.uploadfile` (XLSX заказов, отчёт об избытках) | еженедельная выгрузка |

Правило ТЗ сохраняется: отправка заказа поставщику только после подтверждения ответственного, интеграции создают задачи и черновики, не отправляют сами.

## Как это устроено в коде

`backend/app/integrations.py` описывает интерфейсы `DataSource` (получить products/suppliers/sales/stock/in_transit/stockouts как DataFrame) и `OrderSink` (передать утверждённый заказ / уведомление). Реализации: `CsvSource` (сегодня, работает), `OneCODataSource` и `Bitrix24Sink` (каркас с маппингом объектов выше, требуют URL и учётные данные, помечены `NotImplementedError`). Движок и API от источника не зависят: `Dataset` строится из любого `DataSource`.
