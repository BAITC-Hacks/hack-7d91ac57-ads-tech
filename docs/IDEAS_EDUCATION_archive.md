# Банк идей — трек 07 «Образование» (партнёр: Arizona State University)

Задание неизвестно до 13:00. Этот файл нужен, чтобы за 20 минут сопоставить задачу с готовым сценарием, а не придумывать с нуля.
Контекст партнёра: ASU + OpenAI (ChatGPT Edu для всех студентов, ~700 проектов AI Innovation Challenge, персональный AI-тьютор, учебный дизайн, поддержка преподавателей). ASU открывает InnoTech University в Алматы. Казахстан вводит AI в национальную программу, запускает AI Summer для сотен тысяч студентов.
Значит, вероятные формулировки: персонализация обучения, AI-тьютор с проверяемым результатом, помощь преподавателю (планы, задания, проверка), адаптивные траектории, поддержка казахского/русского/английского, аналитика прогресса, доступность (регионы, село).

## Как выбирать (5 минут)
1. Кто конкретно пользователь: ученик 9 класса / студент 1 курса / учитель / методист / родитель / деканат.
2. Какой измеримый результат за 90 секунд демо: «загрузил материал → получил план урока на 45 минут с заданиями трёх уровней и проверочным тестом».
3. Где агентность: минимум 2 инструмента, которые видно в UI (поиск по материалам, генерация теста, проверка ответа, расчёт прогресса, календарь).
4. Данные за 20 минут: свои PDF/DOCX (учебники, программы), синтетика от LLM, открытые данные.

## Сценарии (готовы к адаптации под задание)

### A. Учитель: «Конструктор урока из учебника» ⭐ самый быстрый
Пользователь: учитель 7 класса. Загружает главу учебника (PDF/DOCX) → агент: search_documents → план урока на 45 мин → дифференцированные задания (3 уровня) → тест из 5 вопросов с ключом → экспорт в DOCX.
Инструменты: search_documents, generate_quiz, export_docx. Данные: любой учебник PDF. Инновация: привязка к ГОСО/учебной программе, три уровня сложности.
Риск: «это просто промпт». Ответ: RAG по конкретному учебнику + структурированный вывод + экспорт.

### B. Ученик: «AI-тьютор с диагностикой пробелов» ⭐ ближе всего к ASU
Ученик отвечает на 5–7 вопросов по теме → агент строит карту пробелов (граф навыков) → даёт объяснение только по пробелам → повторная проверка → прогресс в %. Сократовский режим: не даёт ответ, ведёт наводящими вопросами.
Инструменты: diagnose(skills), explain(skill, level), check_answer, progress_store. Данные: банк вопросов по теме (сгенерировать 30 штук LLM за 5 минут, положить в data/).
Инновация: mastery-based, не чат. Демо-метрика: до/после.

### C. Проверка письменных работ с рубрикой
Учитель загружает рубрику + 20 эссе (или ответов) → агент оценивает по критериям, выделяет цитаты-обоснования, находит подозрение на AI-текст/плагиат внутри пачки, формирует обратную связь каждому ученику и сводную таблицу классу.
Инструменты: grade(essay, rubric) со structured output, similarity(pairwise), summarize_class. Данные: синтетические эссе (LLM), рубрика.
Инновация: обоснования цитатами + «человек утверждает» перед выставлением. Масштабируемость очевидна (время учителя).

### D. Адаптивная траектория / персональный учебный план
Студент: цель (например, «сдать ЕНТ по математике на 100+» или «выучить Python за 8 недель»), текущий уровень (мини-тест), расписание → агент собирает недельный план из блоков, ставит задания, каждый день пересчитывает по факту выполнения.
Инструменты: assess_level, build_plan, reschedule, resources_search. Данные: каталог тем/ресурсов (JSON).
Инновация: пересчёт плана по факту, а не статичный список.

### E. Ассистент деканата/методиста (документы)
Загрузка учебных программ/силлабусов/приказов → агент отвечает на вопросы с цитированием, проверяет силлабус на соответствие требованиям (чеклист), генерирует недостающие разделы.
Инструменты: search_documents, check_compliance(checklist), draft_section. Данные: 3–5 реальных силлабусов PDF из интернета.
Для ASU-контекста: accreditation/learning outcomes alignment.

### F. Многоязычный учебный ассистент (KZ/RU/EN)
Материал на одном языке → объяснение, глоссарий терминов и тест на другом, с учётом уровня. Полезно для сельских школ и для перехода на английский в STEM.
Инструменты: translate_explain, glossary, quiz. Инновация: терминологическая согласованность через глоссарий.

### G. Speech / устная практика (если задание про языки)
Ученик говорит (Web Speech API в браузере → текст) → агент оценивает, задаёт следующий вопрос. Без серверного STT, чтобы не тратить время.

### H. Аналитика для школы/вуза
CSV с оценками/посещаемостью → агент находит группы риска, объясняет причины, предлагает интервенции, готовит письмо родителям/куратору.
Инструменты: load_csv, stats, risk_model (простая эвристика), draft_message. Данные: синтетический CSV на 500 строк.

## Данные, которые можно взять быстро
- **Свои файлы**: любой учебник/лекция PDF, силлабус DOCX. Заранее скачать 2–3 PDF по школьным предметам на ноутбук (папка template/data-samples/ — положить вечером).
- **data.egov.kz** (открытые данные РК, JSON/XML/Excel, часть через API): реестр школ по регионам `datasets/view?index=rosogrz_mp`, перечень госуслуг образования. Портал бывает недоступен (503) — скачать вечером, если нужен.
- **Синтетика**: за 5 минут LLM генерирует 30 вопросов/20 эссе/500 строк CSV. Честно указать в README и THIRD_PARTY.
- **Открытые корпуса**: Khan Academy-подобные вопросы (GSM8K, MMLU по школьным предметам, ARC) — небольшие выборки через HuggingFace datasets, только если есть сеть.

## Что жюри спросит и заготовленные ответы
- «Чем лучше ChatGPT?» → работает на конкретных материалах школы (RAG), структурированный результат (экспорт, оценки, план), инструменты и память прогресса, проверяемость (цитаты).
- «Галлюцинации?» → ответы с цитатами из источника, human-in-the-loop для оценок, DEMO показать «не знаю» при отсутствии в материалах.
- «Стоимость?» → gpt-4.1-mini: один урок/оценка ≈ доли цента; посчитать latency_ms из ответа API.
- «Масштаб?» → одна школа → район → министерство; мультиязычность; интеграция с Kundelik/Bilimland/LMS через API.
- «Данные учеников?» → локальное хранение, анонимизация, роль учителя как контролёра.
