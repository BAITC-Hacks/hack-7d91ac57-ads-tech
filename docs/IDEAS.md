# Банк идей — трек 05 «Логистика»

Контекст РК: транзит Китай–Европа (Средний коридор), КТЖ, автоперевозки, таможня (АСТАНА-1), последняя миля (Kaspi, Wildberries, Яндекс), склады, холодовая цепь, водители-мигранты, KZ/RU/EN/ZH документы.
Где агентность даёт больше, чем чат: исключения в реальном времени, документы, маршруты с ограничениями, коммуникация с десятками контрагентов.

## Сценарии (адаптировать под ТЗ)

### A. Диспетчер-агент по исключениям ⭐ быстро и зрелищно
Вход: список рейсов (CSV) + события (задержка на границе, поломка, отмена заказа). Агент: оценивает влияние, предлагает 2–3 варианта (перенос, замена машины, перегруз), пишет сообщения клиенту и водителю, обновляет план. Человек утверждает.
Инструменты: get_shipments, eta(route), reroute, draft_message. Данные: синтетика 50 рейсов. Демо-метрика: время реакции диспетчера 40 мин → 2 мин.

### B. Документы: CMR / инвойс / декларация → структурированные данные + проверка
Загрузка PDF/фото документов → извлечение полей (structured output) → сверка между документами (вес, кол-во, HS-код, стороны) → список расхождений → готовый черновик таможенной/транспортной формы.
Инструменты: extract_fields, cross_check, hs_lookup. Данные: 3–5 образцов CMR/инвойсов (сгенерировать). Инновация: сверка, а не просто OCR; grounding цитатами из документа.

### C. Планирование маршрутов и загрузки (VRP)
Заказы с окнами доставки + парк машин → агент вызывает решатель (OR-Tools или жадный алгоритм) → маршруты на карте → объяснение решений словами → пересчёт при новом заказе.
Инструменты: solve_routes (ortools), geocode/route (OSRM public API, без ключа), explain_plan. Карта: Leaflet. Инновация: агент объясняет и переигрывает план по событиям, а не только считает.

### D. Прогноз спроса и запасов на складе
CSV продаж/отгрузок → агент строит прогноз (простая модель), предлагает заказ поставщику, объясняет, что и почему, готовит письмо поставщику.
Инструменты: forecast, reorder_point, draft_po. Данные: синтетика 12 месяцев × 50 SKU.

### E. Биржа грузов: подбор перевозчика и переговоры
Заявка на груз → агент фильтрует перевозчиков (тип кузова, маршрут, рейтинг), запрашивает ставки, сравнивает, готовит договор-заявку. Многоагентная версия: агент-заказчик и агент-перевозчик торгуются.
Инструменты: search_carriers, request_quote, compare, draft_contract.

### F. Трекинг и клиентский сервис
Клиент спрашивает «где мой груз» → агент по трекинговым событиям отвечает с прогнозом ETA, объясняет задержку, предлагает действия. Мультиязычно KZ/RU/EN/ZH.
Инструменты: track(shipment_id), eta, translate.

### G. Таможня и соответствие
Описание товара → HS-код, ставки, требуемые документы, ограничения, чеклист для ЕАЭС/Китай. Grounding по загруженным нормативным PDF.
Инструменты: search_documents (RAG по правилам), classify_hs, checklist.

### H. Последняя миля
Курьер: оптимальный порядок точек, окна, звонки клиентам, перенос по факту недоступности. Агент общается с клиентом в чате и переставляет маршрут.

## Данные и внешние API без ключей
- **OSRM** публичный: `https://router.project-osrm.org/route/v1/driving/{lon},{lat};{lon},{lat}?overview=full` — маршруты и расстояния, без ключа (для демо; в README указать как внешнюю зависимость и заготовить кэш ответов в data/ для DEMO_MODE).
- **Nominatim** геокодинг: `https://nominatim.openstreetmap.org/search?q=Астана&format=json` (1 запрос/сек, User-Agent обязателен).
- **Координаты городов РК** — записать в data/cities_kz.json вручную (Астана 51.169, 71.449; Алматы 43.238, 76.889; Шымкент 42.315, 69.587; Караганда 49.806, 73.085; Актобе 50.283, 57.167; Атырау 47.107, 51.919; Хоргос 44.198, 80.416; Актау 43.65, 51.16; Павлодар 52.287, 76.967; Усть-Каменогорск 49.949, 82.628).
- **Синтетика** через LLM: заказы, рейсы, документы CMR. Честно раскрыть.
- **data.egov.kz**: реестры перевозчиков/пунктов пропуска, если портал жив.

## Ответы жюри
- Чем не ChatGPT → работает на данных компании, вызывает решатель/маршрутизатор, переигрывает план по событиям, человек утверждает.
- Галлюцинации → числа только из инструментов, LLM объясняет и общается.
- Стоимость → одна операция диспетчера ≈ X ₸, latency в UI.
- Масштаб → одна компания → 3PL-оператор → коридор; интеграции 1С, TMS, АСТАНА-1.
