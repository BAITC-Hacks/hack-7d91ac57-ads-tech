# План: автоматический расчёт заказов поставщикам (ТОО «Электрокомплект», трек 05 Логистика)

Старт 13:00, план зафиксирован 13:35. Снимок репо в 18:00.

## Задание (суть)
Сервис, который по истории продаж, остаткам, товарам в пути, stockout-периодам, справочнику поставщиков и категориям формирует рекомендованные заказы поставщикам с обоснованием по каждой позиции. Пользователь: менеджер отдела закупа. Сценарий: запустил расчёт по складу/категории → таблица заказов с обоснованием и срочностью → проверил, скорректировал → утвердил → экспорт. Автоотправка поставщику без подтверждения запрещена. Клиенты обезличены.

## Must have → как закрываем → чем доказываем
| # | Требование | Реализация | Проверка (тест) |
|---|---|---|---|
| 1 | Базовая потребность с учётом всех источников: продажи, остатки, в пути, категории, прогноз прироста | `replenish.py`: need = forecast(LT+review) + safety − stock − in_transit; категория задаёт уровень сервиса/период | `tests/test_musthave.py::test_all_inputs_matter` — изменение in_transit меняет результат |
| 2 | Сезонность и устойчивый рост | месячные сезонные индексы + линейный тренд на десезонализированном ряду | `test_seasonality` — прогноз на пиковый месяц > среднего |
| 3 | Упущенный спрос в stockout | импутация спроса в дни stockout по соседним периодам → потребность выше «сырой» | `test_stockout_compensation` |
| 4 | Разовые крупные заказы, в т.ч. один клиент | робастный z-score (медиана/MAD) по транзакциям + доля одного клиента > порога → исключение из регулярного спроса, отдельная метка | `test_outlier_excluded` — вброс крупного заказа не меняет регулярное кол-во существенно |
| 5 | Список по поставщикам с обоснованием | группировка + шаблонное обоснование с числами (без LLM), LLM-агент отвечает на вопросы «почему» | `test_grouped_with_justification` |

Опционально (если успеваем): срочность по риску дефицита (дни покрытия vs срок поставки) — делаем сразу, дёшево; MOQ/кратность — да; графики трендов по категориям — фронт; экспорт CSV/XLSX — да; «отправка» только как черновик письма после утверждения.

## Роль агента (чем не Excel и не ChatGPT)
Числа считает детерминированный движок (объяснимость, устойчивость). LLM-агент поверх инструментов: «почему по артикулу X 120 шт?», «что если в пути придёт 200?», «покажи критичные позиции поставщика Y», черновик письма поставщику после утверждения. Шаги агента видны в UI.

## Данные
Синтетический набор с реалистичным распределением (разрешено ТЗ): ~80 артикулов, 6 категорий электротоваров, 24 месяца дневных продаж, сезонность (освещение — осень/зима, кабель — лето), тренд роста у части позиций, stockout-периоды, 5–8 разовых крупных продаж одному клиенту, 6 поставщиков со сроками и MOQ, остатки, товары в пути. Формат CSV, совместимый с выгрузкой 1С (колонки как в ТЗ). Загрузка своих CSV через API.

## Основной сценарий (демо 90 сек)
1. Открыть дашборд, выбрать склад/категорию, нажать «Рассчитать».
2. Таблица заказов по поставщикам: артикул, кол-во, срочность, обоснование. Раскрыть строку → график: сырые продажи, очищенные, stockout-зоны, выбросы, прогноз.
3. Спросить агента: «почему 120 по ЛМП-24?» → шаги: explain_sku → ответ с числами.
4. Скорректировать количество, нажать «Утвердить» → экспорт CSV/XLSX для 1С.
Метрика «до/после»: расчёт по 80 позициям 3–4 часа в Excel раз в месяц → 5 секунд, хоть каждый день.
