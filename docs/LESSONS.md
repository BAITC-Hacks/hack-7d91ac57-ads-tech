# Уроки участников похожих хакатонов

Источники: Dev-to-Dev Agentic Engineering Challenge (habr 1034362), Agentic Legal RAG Challenge от EORA (habr 1014520), Вайбатон Friflex и ЦСКА, 4 часа (habr 1041194).

## Что решало исход

1. **Запуск по контракту — главный фильтр.** На Dev-to-Dev «часть финалистов с контрактом не справилась»: `docker run` на порту, /health, smoke-проверка. Победитель имел многоэтапный Docker-образ и DEMO-режим без внешних зависимостей. Ровно наш случай: п. 5.4.16 вылет без права на исправление. → `docker compose up` + `scripts/verify.sh` + DEMO_MODE проверять с нуля в 17:00.

2. **Сданное простое бьёт несданное сложное.** В RAG-челлендже команда делала два решения: простое (чанки по страницам, гибридный поиск, реранкер) дало 0.79 accuracy и было сдано; агентное (иерархические чанки, агент-роутер с 4 инструментами, два LLM-вызова) «не успели сдать из-за ошибок API и дедлайна». → Один быстрый путь «вход → результат» с одним LLM-вызовом должен работать к 14:00. Агентные украшения сверху, не вместо.

3. **Побеждает сбалансированный, не самый смелый и не самый чистый.** Победитель Dev-to-Dev (88 баллов): 6 специализированных инструментов с чётким разделением, DEMO-режим, документация. Второе место с 65 тестами и Pydantic-моделями проиграло, потому что «без ИИ в архитектуре». Другое второе место: 5 агентов, но «сложнее в развёртывании». → ИИ должен быть в архитектуре принятия решений продукта, а не только в процессе разработки. И это должно разворачиваться одной командой.

4. **Документы, которые читало жюри:** CLAUDE.md (правила для ИИ), AGENTIC.md (честный отчёт об итерациях и отвергнутых подходах), DEMO.md (сценарий проверки). Лучшие проекты показывали, как именно ИИ участвовал в архитектуре. → У нас: CLAUDE.md, AI_USAGE.md, docs/DECISIONS.md (аналог AGENTIC.md), README раздел 8 (аналог DEMO.md).

5. **История коммитов отражает процесс.** Проверяющие смотрели её как индикатор; размер Docker-образа тоже (96 МБ против 574 МБ). → Осмысленные сообщения коммитов, slim-образы.

6. **Экономическое обоснование на слайде.** Friflex: «260 раз быстрее и в 21 раз дешевле моушн-дизайнера». Это ровно критерии «ценность» и «потенциал». → Посчитать стоимость запроса и время «до/после», вывести в UI и на слайд.

7. **Роли в команде на 4 часа:** один пишет бэкенд и сложный фронт, остальные подбирают модели, тестируют промпты, считают экономику, делают презентацию. → Даже втроём: код, данные+промпты, питч+README. Не три человека в одном файле.

## Уроки по RAG (если сценарий с документами)

- «Хороший чанкинг — половина успеха». Семантический чанкинг сложен, иерархический даёт фрагменты. Рабочее: чанки по страницам/абзацам с перекрытием + метаданные + regex для типизированных ответов (даты, числа, имена) + реранкер.
- Гибридный поиск (ключевые слова + эмбеддинги) лучше только векторного. У нас есть keyword fallback, при наличии времени объединить.
- Grounding измеряли отдельно (0.63) от accuracy (0.79): жюри ценит ответы с цитатами.

## Уроки по работе с AI-инструментами разработки

- Вайб-кодинг ускоряет рутину (CRUD за 15–20 минут), но плох для дебага («латает симптомы вместо причины»), архитектуры (нужен большой контекст) и нестандартных задач. → Архитектуру и план фиксирует человек в PLAN.md, ИИ реализует по фичам.
- «Не полагаться на ИИ-агентов в сложных пайплайнах: они подменяют решение обходами, проходящими тесты». → Проверять результат глазами на реальных данных, не только тестами.
- Жёсткие ограничения в промптах и negative-инструкции дают предсказуемый выход. Двухуровневая схема: агент выбирает стратегию/инструмент, затем узкий вызов выполняет. Это наш tool-calling цикл.
- Генеративные модели плохо пишут текст в изображениях, особенно кириллицу. Не строить демо на этом.
- Баг можно честно переклассифицировать в фичу, если он не ломает сценарий. Не тратить час на косметику.

## Типичные ошибки финалистов (не повторять)

- Нерабочие решения и сломанные цепочки агентов.
- Слишком простые инструменты без агентного компонента.
- Невоспроизводимое демо: запутанная документация, долгие сборки.
- Амбициозность без дисциплины: мультиагентные системы с проблемами в Docker-сборке.
