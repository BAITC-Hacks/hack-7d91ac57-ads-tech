## 4. Как это работает

### Архитектура

```
┌──────────────┐   HTTP /api    ┌──────────────────┐   OpenAI-compatible   ┌───────────┐
│  Frontend    │ ─────────────▶ │  Backend FastAPI │ ────────────────────▶ │  LLM      │
│  React+Vite  │                │  агентный цикл   │                       │  OpenAI / │
│  :8080       │ ◀───────────── │  tool calling    │ ◀──────────────────── │  NVIDIA   │
└──────────────┘                └───────┬──────────┘                       └───────────┘
                                        │ инструменты
                     ┌──────────────────┼──────────────────┐
                     ▼                  ▼                  ▼
              search_documents    <tool_2>           <tool_3>
              (RAG по файлам)     (<что делает>)     (<что делает>)
                     │
                     ▼
              data/ (SQLite, индекс фрагментов)
```

**Поток основного сценария:** <вход> → <инструмент 1> → <инструмент 2> → <структурированный результат> → <экспорт>.

### Агент и инструменты

| Инструмент | Что делает | Файл |
|---|---|---|
| `search_documents` | поиск по загруженным материалам, возвращает фрагменты с источником | `backend/app/tools.py` |
| `<tool_2>` | | |
| `<tool_3>` | | |

Цикл: модель получает список инструментов, вызывает нужные, результаты возвращаются в контекст, до 8 раундов (`backend/app/llm.py`). Шаги показываются пользователю в UI.

### Чем отличается от «просто ChatGPT»

- <Работает на материалах конкретной школы, отвечает цитатами, говорит «не знаю» вне материалов.>
- <Структурированный результат, который можно забрать: DOCX / таблица / план.>
- <Механизм инновации: карта пробелов / сократовский режим / агент-проверяющий / утверждение учителем.>

### Надёжность

- `DEMO_MODE=true` — основной сценарий работает без внешних API на заготовленных данных.
- Ошибки инструментов возвращаются модели как JSON, а не роняют запрос.
- Ответы с цитатами; <human-in-the-loop там, где выставляются оценки>.

## 6. Установка

**Системные требования:** Docker 24+ с Compose v2 (рекомендуется). Без Docker: Python 3.12, Node.js 20+. 2 ГБ RAM, 1 ГБ диска. Доступ в интернет к LLM API (не нужен при `DEMO_MODE=true`).

```bash
git clone https://github.com/BAITC-Hacks/hack-7d91ac57-ads-tech.git
cd hack-7d91ac57-ads-tech
cp .env.example .env
```

Откройте `.env` и заполните `LLM_API_KEY` (демо-ключ передан в форме сдачи) или установите `DEMO_MODE=true`.

## 7. Запуск

**Вариант A — Docker, одна команда:**
```bash
docker compose up --build -d
```
Готовность: `docker compose ps` показывает `backend … (healthy)`. UI: http://localhost:8080. API: http://localhost:8000/api/health.

**Вариант B — локально, два терминала:**
```bash
make setup      # создаёт backend/.venv и ставит frontend/node_modules
make backend    # API на :8000 с автоперезагрузкой
make frontend   # UI на :5173, /api проксируется на :8000
```

**Остановка:** `docker compose down` (добавьте `-v`, чтобы удалить данные).

## 10. Проверка

1. `bash scripts/verify.sh` — health, загрузка тестового файла, вопрос агенту. Последняя строка `OK`.
2. Пройти [основной сценарий](#3-основной-сценарий-что-проверять) в UI по таблице шагов.
3. `DEMO_MODE=true` + перезапуск — сценарий проходит без ключа.

### Если не запускается

| Симптом | Решение |
|---|---|
| Порт 8000 или 8080 занят | в `.env`: `API_PORT=8001`, `WEB_PORT=8090` |
| В логах backend `401`/`429` от LLM | проверить `LLM_API_KEY`, лимиты; либо `DEMO_MODE=true` |
| `backend` не становится `healthy` | `docker compose logs backend` — ошибка будет в последних строках |
| Нет Docker | вариант B из раздела 7 |
| Файл не загружается | поддерживаются PDF, DOCX, TXT, MD, CSV, JSON; PDF-сканы без текстового слоя не читаются |
