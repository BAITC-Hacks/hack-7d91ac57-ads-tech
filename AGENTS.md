# HackAlem AI — правила работы в этом репозитории

Контекст: 5-часовой хакатон, 23.09.2026 13:00–18:00 (Астана). Снимок репо в 18:00 = финальная версия.
Трек 05 «Логистика». Команда Ads Tech. Полный плейбук: ../GUIDE.md (вне репо).

## Жёсткие правила (нарушение = дисквалификация или вылет на техпроверке)
1. Коммит с реальным прогрессом минимум каждые 30 минут. Скрипт `scripts/autocommit.sh` уже делает это, но осмысленные коммиты с понятными сообщениями важнее.
2. README.md — это то, по чему судят (эксперты и AI-судья). Организаторы на мастер-классах отдельно подчеркнули понятный README. Он должен ВСЕГДА соответствовать текущему коду, начинаться с блока «Быстрый старт» из 3 команд и одного предложения «что вы увидите». Обновляй разделы 2 (что реализовано, до/после), 3 (сценарий проверки по шагам), 4 (архитектура, инструменты) и 11 (ограничения) при каждом изменении функциональности. Плейсхолдеры `<...>` к 17:40 должны исчезнуть.
3. Решение должно запускаться одной командой `docker compose up --build -d` и проверяться `bash scripts/verify.sh`. Проверяй это сам перед каждым крупным коммитом.
4. Никаких секретов в git. Ключи только в .env; .env.example актуален.
5. DEMO_MODE=true должен давать работающий основной сценарий без внешних API.
6. Любой новый сторонний компонент, модель, датасет → строка в THIRD_PARTY.md.
7. Каждое значимое решение и отвергнутый подход → строка в docs/DECISIONS.md. Использование AI-инструментов → AI_USAGE.md.
8. Сначала самый простой путь «вход → результат» с одним вызовом LLM, он должен работать к 14:00. Агентные усложнения только поверх работающего. Сданное простое бьёт несданное сложное (docs/LESSONS.md).

## Приоритеты по времени
- 13:00–13:30 — разбор задания, выбор сценария, план в docs/PLAN.md, первый коммит.
- 13:30–16:00 — основной сценарий end-to-end (сначала уродливо, но работает).
- 16:00–17:00 — качество: UX, обработка ошибок, тестовые данные, DEMO_MODE.
- 17:00–17:40 — README финал (все `<...>` заменены, скриншот docs/screenshot.png), THIRD_PARTY, verify.sh, docker с нуля.
- 17:40–18:00 — заморозка. Только README и питч. Финальный push до 17:55.

## Стек
FastAPI (backend/app), React+Vite+Tailwind (frontend/src), OpenAI-совместимый LLM (backend/app/llm.py), SQLite.
Инструменты агента добавляются декоратором @tool в backend/app/tools.py.

## Стиль
- Минимум абстракций. Один файл на фичу. Никаких преждевременных рефакторингов.
- Ошибки наружу с понятным текстом, не молчаливые падения.
- Русский язык в UI и README.

## Ты — Codex. Параллельная работа с Claude Code (docs/TEAMWORK.md)
- Ты владеешь `frontend/**`. `backend/**`, README, THIRD_PARTY, PLAN, DECISIONS принадлежат Claude Code: не редактируй, проси через `docs/HANDOFF.md`.
- Строй UI строго по `docs/API.md`. Если реальный ответ backend расходится с контрактом, напиши в `docs/HANDOFF.md`, не чини backend сам.
- Backend уже запущен на :8000 человеком. Не запускай второй. Для UI: `cd frontend && npm run dev` (порт 5173, /api проксируется).
- Перед коммитом: `cd frontend && npm run build` должен проходить. Коммить только `git add frontend AI_USAGE.md`, сообщение `feat(ui): …` или `fix(ui): …`. Никогда `git add -A`, `--force`, `reset --hard`.
- После каждой задачи допиши строку в `docs/HANDOFF.md` и свою строку в `AI_USAGE.md`.
- UI на русском. Панель «Шаги агента» и `latency_ms` всегда видны: это доказательство агентности для жюри.
